# Evaluation issue report — 26 September 2026

## Summary

**Follow-up:** The sections E01–E06 below record the original baseline. Recovery
changes have since been added, but successful live proposal generation remains
unverified. The newly identified evidence-flow issue E07 is fixed and checked
offline. See the current follow-up in `three_domain_review.md` for spending and
the remaining quality-evaluation gap.

Twelve end-to-end attempts covered robotics, accessibility, and medicine in
sequential and parallel modes: six before and six after the duplicate-source
fix. None produced final proposals. Two defects were fixed; fixture coverage
and model-output compliance still block the quality comparison.

This report also includes the earlier nine-case Critic baseline. All source
fixtures are synthetic. Findings are not evidence of production readiness.

## Fixed defects

### E01 — Repeated sources rejected as conflicting

- **Observed:** The initial six end-to-end attempts failed duplicate-source checks.
- **Cause:** Scout and Library compared whole receipts, including query IDs and
  capture metadata that can differ for identical source content.
- **Fix:** Compare source content and full text while ignoring query/capture
  metadata. Retain the first receipt; still reject genuinely changed content.
- **Verification:** Regression tests cover both workers. The second set of six
  live attempts passed this failure point.

### E02 — Tiny residual reserved costs

- **Observed:** Parallel settlements left floating-point remainders, including
  a negative reserved cost of approximately `-2.17e-19` USD.
- **Impact:** Misleading budget counters, not evidence of material overspending.
- **Fix:** Clamp negative remainders to zero and clear reserved cost when no
  reserved tokens remain.
- **Verification:** Added a regression test; eight budget tests passed. This
  correction was tested offline, not through another paid comparison.

## Open blockers

### E03 — Success fixtures cannot meet source coverage

- **Observed:** Accessibility and medicine each supplied two usable sources;
  policy requires three. Both modes returned insufficient coverage.
- **Impact:** These fixtures cannot demonstrate a successful full run under the
  current policy. This is a fixture/policy mismatch, not a failed guardrail.
- **Next:** Add relevant synthetic sources and version the fixtures. Retain
  two-source cases separately as expected-failure tests; do not relax the gate
  just to make the comparison pass.
- **Acceptance:** Both modes meet coverage on the revised success fixtures.

### E04 — Candidate output violates the schema

- **Observed:** Robotics sequential returned `why_it.matters` instead of the
  required `why_it_matters` for candidate 12; validation rejected the output.
- **Impact:** Candidate generation stopped before downstream evaluation.
- **Next:** Review the schema supplied to generation and strengthen output
  compliance. Any repair/retry must stay within the shared budget.
- **Acceptance:** Valid candidate responses on repeated frozen-case runs;
  malformed responses remain safely rejected in regression tests.

### E05 — Planner exceeds the query result cap

- **Observed:** Robotics parallel produced `scout-q-06` with a result limit
  above `max_results_per_query`.
- **Impact:** The runtime correctly rejected the query, preventing completion.
- **Next:** Make resolved limits explicit to the planner and test boundary
  values. Keep runtime enforcement authoritative.
- **Acceptance:** Planned queries respect configured limits in both modes.

### E06 — Critic confuses missing evidence with contradiction

- **Observed:** The component baseline scored 6/9. `missing_measurement`,
  `missing_generalization`, and `missing_injection` were incorrectly labeled
  contradictory instead of unsupported. No false-support predictions occurred.
- **Status:** The Critic prompt was clarified; improvement is not yet measured.
- **Next:** Rerun the component baseline and additional held-out/adversarial
  cases. Keep the extra runtime-verifier decision open until measurements
  justify its latency and cost.

## Evaluation limitations and follow-up

### E07 — Prepared fixture evidence never reached Critic

- **Observed:** The frozen adapter read only `sources.json`. Library rebuilt
  chunks from short summaries, leaving details in `chunks.json` unavailable.
- **Fix:** Validated passages now travel to Library without expanding Scout's
  source prompt. Library preserves passage IDs and distinct source summaries;
  normal retrieval selects Critic context. Source-byte accounting includes the
  passages, and case/checkpoint fingerprints include both fixture files.
- **Verification:** Offline tests inspect the actual Critic prompt in both
  modes for the dataset permission passage. They also check metadata-only
  requests, invalid source links/duplicate IDs, byte caps, and changed-input
  fingerprints. Full suite: 158 tests passed; fixture validation passed.
- **Live follow-up:** Robotics indexed all eight summary/prepared chunks and
  Critic cited a prepared passage. No schema/citation failures occurred, but
  Scout produced two of twelve ideas and both failed evidence sufficiency.
  Zero proposals resulted; see `three_domain_review.md` for the cost and findings.
- **Limit:** Evidence delivery is verified. This does not establish the quality
  of model judgments or successful proposal generation.

- **Quality is unmeasured:** No final proposals exist from these live attempts.
  Human rubric scoring and final-proposal comparison remain pending.
- **Latency is not comparable as successful-run performance:** Runs stopped at
  different stages. Independent model responses and varying candidate counts
  also prevent attributing differences solely to scheduling mode.
- **Usage uncertainty remains:** Canceled calls have $0.00406305 reserved for
  unknown usage. Combined reported cost is $0.02218755; total accounted allowance
  is **$0.02625060 of $1**. These are estimates, not provider-billing reconciliation.
- **Reproducibility is bounded:** Frozen inputs do not freeze model responses.
  The Critic baseline recorded an alias, not a resolved model snapshot. Offline
  deterministic mode-equivalence tests do not prove live output equivalence.

Recommended order: correct success fixtures; address candidate/query compliance;
rerun both modes on identical revised fixtures and limits; score final proposals;
then extend claim-support testing. Preserve this failure baseline.
