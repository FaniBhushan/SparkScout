# Deadline demo fallback plan

This is a contingency, not the normal acceptance path. The main deadline risk is
getting usable proposals from the live run and all three frozen domains. If time
runs short, prioritize an honest demo plus evaluation results that can be
reproduced. Document any domain that returned no proposals. Do not make a failed
run look successful.

## Preferred fallback order

1. **Preserve reproducibility.** Run the same fixed evaluation cases with the
   recorded inputs and limits; retain the result reports and explain any domain
   that returned no proposals.
2. **Keep the demo honest.** Show a live run if it yields a usable proposal. If it
   does not, demonstrate the workflow with a clearly labeled frozen-fixture
   example and say that its evidence is synthetic. Keep that example separate
   from live quality, cost, and source claims.
3. **Do not pad results or disguise failures.** Requested counts are targets, not
   permission to invent proposals. Keep the rubric and hard gates unchanged for
   the deadline demo.

## Demo wording

State which example is live and which uses frozen synthetic fixtures. Show the
actual source links, proposal citations, and trace. If a domain returned no
proposals, say so and show the reproducible evaluation result. Do not claim a
three-domain quality success unless all three domains produced reviewable results.
Keep the static rubric for this deadline; request-specific dynamic criteria
remain future work.
